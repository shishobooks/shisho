# Plugin System

Add a rule here only when it outlives a single fix and neither code nor a check can convey it; prefer adding the check. Topic detail goes in `docs/agents/plugins/`, history in commit messages.

Plugins are third-party JavaScript run in sandboxed Goja VMs, one VM per plugin, with access to the `shisho.*` host APIs. The public contract (manifest fields, hook contexts and results, host API behavior, timeouts) is documented in `website/docs/plugins/manifest-hooks-reference.md` and `host-api-reference.md` and typed in `packages/plugin-sdk/*.d.ts`; read those rather than a copy here.

- Read `docs/agents/plugins/identify-apply.md` before changing `POST /plugins/search` or `POST /plugins/apply`, `persistMetadata`, or any `handler_attribution`, `handler_relationships`, `handler_identifiers`, `handler_convert`, or cover-apply code.
- Read `docs/agents/plugins/lifecycle-and-install.md` before changing install, update version, reload, enable, disable, uninstall, the local scan, `LoadAll`, the update check, or repositories.
- Read `docs/agents/plugins/extending.md` before adding a host API, a hook type, or a manifest capability.

## Plugin SDK

`packages/plugin-sdk/` is the published contract for plugin authors, so it changes in the same PR as the Go it mirrors. Prefer additive changes (new optional fields); removing or retyping a field breaks plugins. `sdk_sync_test.go` checks the names: host APIs (`TestPluginSDK_HostAPIsMatchGo`), hook names (`TestPluginSDK_HookNamesMatchGo`), manifest fields (`TestPluginSDK_ManifestMatchesGo`), and enricher metadata fields (`TestPluginSDK_MetadataFieldsMatchGo`). Nothing checks hook context fields, the `ParsedMetadata` field mapping, or whether a change breaks plugins, so those stay on you.

| Go change | SDK and docs to update |
|-----------|------------------------|
| Host API (`hostapi*.go`) | `host-api.d.ts` (`ShishoHostAPI`), `testing/index.ts` (`createMockShisho` must supply every required member or `tsc` breaks for every plugin author), `website/docs/plugins/host-api-reference.md` |
| Hook context or result (`hooks.go`, `runtime.go`) | `hooks.d.ts` (`ShishoPlugin`), `website/docs/plugins/manifest-hooks-reference.md` |
| Manifest or capability (`manifest.go`) | `manifest.d.ts`, the manifest reference page |
| `mediafile.ParsedMetadata`, `ParsedAuthor`, `ParsedIdentifier`, `ParsedChapter` | `metadata.d.ts`, the JS-to-Go parsing in `hooks.go` (`parseParsedMetadata` and friends), `hooks.d.ts` when the metadata appears in a hook context |

SDK fields are camelCase (`seriesNumberEnd`); snake_case (`series_number_end`) belongs only to Go JSON and the HTTP apply payload. Fields tagged `json:"-"` (`ParsedMetadata.CoverData`, `DataSource`, `FieldDataSources`, `ParsedIdentifier.Source`) are host-internal: no SDK change, and never populated from plugin output.

## HTTP API types

Every plugin HTTP payload is a named struct in `types.go`, generated by tygo together with `manifest.go` and `repository.go`.

- **Manifest and repository-index passthrough fields keep camelCase** (`declaredFields`, `fieldSettings`, `imageUrl`, all of `ConfigField`, `Capabilities`, `PluginVersion`); fields the server adds to the same responses are snake_case (`is_official`, `confidence_threshold`). Renaming a passthrough field is a breaking wire change.
- `AvailablePluginResponse` is the HTTP response; `AvailablePlugin` in `repository.go` is the repository-index entry. `app/types/index.ts` aliases generated names to the frontend's (`AvailablePluginResponse as AvailablePlugin`, `AnnotatedPluginVersion as PluginVersion`, `Capabilities as PluginCapabilities`, `EnrichSearchResult as PluginSearchResult`).
- Routes are registered in `routes.go` as four `/plugins` groups split by permission plus per-library routes on `/libraries`, none of them in Demo Mode. Which permission guards each group is under "Route families with non-obvious guards" in `docs/agents/backend/auth-and-permissions.md`.
- `handler_shape_test.go` pins the exact JSON keys of the search and config responses. Extend it when adding fields to a heavily consumed response.

## Concurrency

- **Goja VMs are single-threaded.** `Runtime.mu` serializes hooks and reloads; `Manager.mu` guards only the registry map. Every hook runner takes `rt.mu.Lock()`, never `RLock`: the parallel scan worker pool calls hooks from many goroutines, and two goroutines in one VM corrupt it. Different plugins run concurrently.
- **One lifecycle lock per plugin.** Install, update, reload, enable, disable, PATCH, uninstall, `LoadAll`, `LoadPlugin`, `ReloadPlugin`, `UnloadPlugin`, and the update check's write each hold `lockPlugin(scope, id)` and re-read the row inside it. Take it before `Runtime.mu`, never inside a hook, never inside a database transaction. Downloads and staging happen before the lock, so a slow download never blocks a disable.
- **Column-scoped writes only.** There is no full-row `UpdatePlugin`, on purpose: a full-row write from a stale read reverts concurrent changes. Use `Service.UpdatePluginColumns` or `applyVersion`. Transitions write `lifecycleColumns`; PATCH writes `auto_update` and `updated_at`; the update check writes only `update_available_version`.
- **`applyVersion(ctx, row, rt, insert)` is the only place a loaded version is stored.** It writes the row, manifest-derived identifier types, and the reconciled hook order (`reconcileHookOrder`) in one transaction, then registers `rt` only when the row is Active. A nil `rt` writes only the row; a database fault rolls back and keeps the old runtime.
- **`setRuntime` takes the write lock of the runtime it replaces**, so registering waits for hooks in progress.

## Load failures and identifiers

- **Load failures are typed.** `loadRuntime` returns a `*LoadError` (check with `asLoadError`) when the plugin itself is at fault: manifest, script, host version requirement, or a manifest id that differs from its directory. That is recorded on the plugin and surfaces as `422 plugin_load_failure`. Any other error (host API injection, a database fault) is a server fault: 500, logged by `LoadAll`, stored state untouched. A manifest mistake that would otherwise surface as a database error (for example a repeated `identifierTypes` id) must be rejected in `ParseManifest` so it stays a `LoadError`.
- **Scopes and ids are single path segments.** `validPathSegment` rejects empty values, more than `maxPathSegmentLen` bytes, a leading dot (keeps ids clear of `.staging` and `.trash`), `/`, `\`, and control characters. Every route taking `:scope/:id` that touches the plugin directory calls `validatePluginRef` first. `ParseManifest` applies the same rule to the manifest id.

## Hooks

- **Manifest and JS must agree in one direction.** A JS hook the manifest does not declare fails the load; a declared capability with no JS hook is silent. Invalid enricher `fields` names fail the load; a missing or empty `fields` disables only the enricher hook (stored as a load warning).
- **File parser and converter `mimeTypes` match with `(*mimetype.MIME).Is`**, never string equality, so registered aliases and MIME parameters keep matching (`pkg/worker/scan_unified.go`, `scan.go`).
- **`parseChapter` does not check the sign of `startPage`.** Chapter policy lives in the scan (`dropNegativeStartPageChapters`, see `docs/agents/backend/scanner.md`). Keep sign checks out of `pkg/plugins` and the SDK types.
- **Search results are `mediafile.ParsedMetadata` directly** (`parseSearchResponse`); there is no separate `enrich()` hook. The HTTP handler wraps them in `EnrichSearchResult` only for the response. Fields the manifest does not declare are stripped with a warning; declared fields the user disabled are stripped silently.
- **Hook modes.** `GetOrderedRuntimes` returns only `enabled` plugins (automated scans); `GetManualRuntimes` returns `enabled` and `manual_only` (Identify). Per-library hook order and field settings fully override the global ones; no field-settings rows means every declared field is enabled.
- Scan-time enrichment and its merge live in `runMetadataEnrichers` (`pkg/worker/scan_unified.go`, see `docs/agents/backend/data-sources-and-merges.md`); data source priority is in `pkg/AGENTS.md`.

## Host APIs

- **Blocking host APIs must honor `Runtime.hookCtx`.** `invokeHook` stores the hook's context there; `shisho.sleep`, HTTP, ffmpeg, and shell select on it, because `vm.Interrupt()` fires only between JS statements and cannot cancel a native wait. A new blocking API that ignores it holds `Runtime.mu` past the hook timeout.
- **File modes come from `FSContext.writeMode`.** `writeFile`/`writeTextFile` create 0600 inside the plugin's directory, data directory, or `tempDir()` (`isInPrivateDir`, checked first even when another rule also allows the path) and 0644 everywhere else permitted; overwriting an existing file keeps its mode, since `os.WriteFile` applies the mode only on creation. There is deliberately no SDK option to choose a mode. `NewFSContext` makes the plugin and data directories absolute because config may give relative paths and every check compares absolute paths.
- **A host API that writes or stages files sets the mode at creation** ("File Modes Are Set at Creation" in `pkg/AGENTS.md`): `fileutils.CreateTemp`, `fileutils.WriteFileAtomic`, or `os.OpenFile` with the mode; never create then chmod (forbidigo rejects `Chmod`).
- **`extractZip` creates files with `f.Mode().Perm()|0o600`, never the raw `f.Mode()`.** Go passes setuid, setgid, and sticky bits through to `open(2)`; the 0600 floor keeps read-only entries overwritable. Its test uses empty entries because an unprivileged write makes the kernel clear setuid, which would hide a regression.
- `shisho.shell.exec` runs the allowlisted binary directly, with no shell. `shisho.yaml` uses `gopkg.in/yaml.v3`, which never instantiates objects from custom tags, so untrusted YAML cannot execute code.

## Filesystem sandbox (FSContext)

Each hook invocation gets its own `FSContext`; temp directories are removed when the hook returns.

| Path | Read | Write |
|------|------|-------|
| Plugin's own directory, data directory, temp directory | Always | Always |
| Hook-provided read-write paths (converter `sourcePath`/`targetDir`, parser `filePath`, generator `destPath`) | Always | Always |
| Enricher target file (`SetReadOnlyAllowedPaths`, file only, not its directory) | Always | Never |
| Anywhere else | `fileAccess` `read` or `readwrite` | `readwrite` only |

The read-only list is consulted by `isReadAllowed` only, never `isWriteAllowed`. An enricher needing sibling files declares `fileAccess: read`; one modifying the target declares `readwrite`. Known gap: `isPathWithin` does not resolve symlinks, and `filepath.EvalSymlinks` fails for not-yet-existing write targets, so a fix must handle both.

## Testing

- **`t.Parallel()`** belongs on pure-function tests and on tests that build their own database, plugin directory, and manager (`newLifecycleEnv`). Leave it off tests that share a manager or runtime, tests that set the package globals `AllowedDownloadHosts` or `AllowedFetchHosts` (every downloading install or update test, including those using `servePackage`), and tests that call `testumask.Set` (the `*_permissions_unix_test.go` files).
- **Prove lock waits without sleeping.** `Manager.onLockWait`, when set, runs just before `lockPlugin` blocks; `servePackage` can hold a download until `releaseNow`. Use these instead of `time.Sleep` in concurrency tests.
- Inline test plugins: `installTestPlugin(tc, pluginDir, id, manifestJSON, mainJS)` in `pkg/worker/scan_plugins_test.go`. Fixture plugins live in `pkg/plugins/testdata/`.
