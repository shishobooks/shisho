# Reference Books never have a Read-through underway

Some Books get dipped into rather than read through: a cookbook opened for one recipe, a textbook for one chapter, an anthology for one story. A Read-through is one pass through a Book, so these never fit. A recipe lookup sat in Currently Reading for days, then had to end as Read or Did Not Finish, and either one counted a book in Reading Stats that was never read or abandoned. Deleting the Read-through instead lost the time spent, and the next visit started another one. So **Reference** is a Reading Status the user chooses for a Book, stored on the same per-user, per-Book record as Rating and To Read. While a Book is Reference, it never has a Read-through underway. Every visit is looking something up, as it already is in a finished Book: the Reading Position moves and the Reading Sessions count toward time, but nothing counts as finished or abandoned.

## Considered options

- **A third Read-through outcome** next to finished and abandoned, for ending a Read-through without either. Rejected because a lookup still isn't a pass through the Book, and a Book the user hadn't opened yet would still land in Currently Reading on its first visit. The outcome would only fix how a visit ends.
- **A property of the Book**, set with its metadata, that applies to everyone. Rejected because whether a Book is read through or dipped into depends on the reader: one user works through a textbook cover to cover, another looks things up in it. Genres and tags already say what kind of Book it is.

ADR 0013 rejected a stored status alongside the Read-throughs because the two drift. Reference doesn't, because it copies nothing the Read-throughs hold. It records a choice they can't express, and the controls keep the two apart: choosing Reference ends anything underway and takes the Book off To Read, and starting or queueing clears Reference.

## Consequences

- **Reference outranks the ended Read-throughs when the status is worked out.** A textbook finished in 2024 and kept for reference now shows Reference, and its 2024 finish still counts in that year's Reading Stats as before.
- **Choosing Reference ends any Read-through underway by turning it into plain Reading Sessions.** Its sessions and its history of Reading Position updates are kept, detached as a lookup's are, and keep counting toward time. The Read-through and its begin day are deleted, and the Reading Positions stay where they are. A user deleting a Read-through otherwise takes its sessions with it (ADR 0013). When a Read-through is underway, the controls confirm first, singly and in bulk, because Reading History loses an entry. Choosing Reference also takes the Book off To Read.
- **Choosing any other status clears Reference**: starting a Read-through, Mark as read, or Add to To Read. Removing Reference on its own records nothing, so the status falls back to what the Read-throughs say. A Book never read through starts a Read-through on its next real progress, as any unread Book does.
- **Apart from Book merges, only an explicit choice in Shisho's own controls changes a Reference Book's status**, on the web or in the Shisho app. Nothing inferred does, in any reader including Shisho's own: position updates never start, finish, or reopen a Read-through in it. In a cookbook, flipping to the index at the back would otherwise finish it. Undo on an automatic finish is refused once the Book is Reference, since Reference is the later choice. Nothing Kobo or KOReader reports changes it either, though those devices still move the Reading Position and add Reading Sessions.
- **Devices can disagree with Shisho about a Reference Book.** Kobo has no matching status, so Shisho sends it as ready to read along with its position, while the Kobo may show it as reading. KOReader is sent no status, which leaves whatever status KOReader already has, such as reading, in place. Shisho drops the status those devices report back for it.
- **Activity is judged by the status when Shisho records it.** Positions and sessions that arrive late, such as from a KOReader that was offline, are placed as they are today, by day. Reference adds no replay of late activity.
- **The latest explicit choice wins when the Shisho app's choices arrive late.** The app's journal places each event at the instant it happened (ADR 0024). So Shisho keeps the instant of the user's latest explicit status choice for the Book, of any kind and whether or not the Book was Reference at the time, and whether that choice was Reference. A late event is ordered against it.
  - A Reference choice made offline before a later explicit choice elsewhere doesn't apply, whether that later choice was Remove from Reference, Read again, Mark as read, or Add to To Read.
  - A start or resume made offline before a later Reference choice doesn't apply, since choosing Reference would have ended it.
  - A finish or abandon made offline before a later Reference choice is recorded as an ended Read-through with no begin day. It is history only: it takes no Reading Sessions, then or later, so the sessions stay detached. Reference and To Read are left as they are.
- **Merging Books never deletes a user's Read-throughs to keep Reference.** For each user, the merged Book keeps whichever Book's latest explicit status choice is later, with its instant, so late events still order correctly. When the merged Book then has a Read-through underway or a place on To Read, Reference is cleared for that user, and the instant stays. Merging is an admin's action, not the user's choice.
- **While a Book is Reference, it adds time to Reading Stats and nothing else.** Its earlier Read-throughs count as before.
- **The Currently Reading page never shows a Reference Book.** It shows up wherever a Reading Status can be filtered or sorted on, sorted after Did Not Finish.
